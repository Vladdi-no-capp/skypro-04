# Маршрутизация приложения English Cards — проектное решение

## Зачем это делаем

Преобразовать текущий репозиторий в React-приложение для изучения английских слов по карточкам и выполнить требования домашней работы по маршрутизации и авторизации. Работа ведётся учебными шагами: ученик пишет небольшие части самостоятельно, после каждого шага результат проверяется и объясняется.

## Цели

- Запускать приложение из корня репозитория командой `npm run dev`.
- Создать семь компонентов страниц в `src/pages`: вход, регистрация, каталог карточек, просмотр/редактирование карточки, добавление карточки, выход и 404.
- Настроить маршруты `/`, `/login`, `/register`, `/new-card`, `/card/:id`, `/exit` и `*`.
- Защитить каталог и рабочие маршруты состоянием `isAuth`.
- Реализовать предсказуемый вход и выход через элементы интерфейса.
- Получать `id` карточки через `useParams` и явно показывать его на странице.
- Стилизовать все немодальные страницы с помощью Styled Components.
- Подготовить отдельную ветку и PR после завершения и проверки.

## Предметная область

- Главная страница показывает учебные карточки английских слов.
- Карточка содержит как минимум английское слово и русский перевод.
- Страница `/card/:id` показывает `id`, слово и перевод и предоставляет учебный интерфейс редактирования.
- Страница `/new-card` предоставляет форму добавления новой карточки.
- В начальном демонстрационном наборе обязательно есть карточки с `id` 1 и 42.
- Формы добавления и редактирования демонстрационные: отправка формы возвращает на `/`, но не меняет набор данных. Цель этой домашней работы — маршрутизация.

## Не входит в эту домашнюю работу

- Настоящий сервер, API, база пользователей или проверка пароля.
- Сохранение авторизации после обновления страницы через localStorage/cookies.
- Постоянное хранение созданных или изменённых карточек.
- Перенос предметной области старой канбан-доски в новое приложение.

## Ограничения и принятые решения

- Используем Vite в корне текущего репозитория.
- Используем React, `react-router-dom` и `styled-components`.
- Старые `main.html`, `modal/`, `css/` и `js/script.js` не считаются архитектурой нового приложения. Сначала оставляем их нетронутыми, затем удаляем отдельным проверяемым шагом, когда React-версия запускается. Папка `images/` удаляется только после проверки, что React-версия не использует её ресурсы.
- `BrowserRouter` инициализируется один раз в `src/main.jsx`.
- Переходы выполняются через `Link`, `Navigate` и `useNavigate`, без обычных HTML-переходов с полной перезагрузкой.
- `isAuth` хранится через `useState` в `App.jsx`; начальное значение — `false`.
- `App.jsx` содержит только состояние авторизации и подключение `AppRoutes`; логика каталога находится в `CardsPage` и вложенных компонентах.
- `ProtectedRoute` принимает `isAuth` и дочерний элемент. При `false` возвращает `<Navigate to="/login" replace />`.
- Формы обрабатываются через `onSubmit` и `event.preventDefault()`.
- Вход вызывает `setIsAuth(true)`, затем переводит на `/`.
- Регистрация не создаёт настоящего пользователя: отправка формы переводит на `/login` без автоматической авторизации.
- Подтверждение выхода вызывает `setIsAuth(false)`, затем переводит на `/login`; отмена возвращает на `/`.
- `/`, `/new-card`, `/card/:id` и `/exit` защищены. `/login`, `/register` и `*` доступны без авторизации.
- Если авторизованный пользователь вручную открывает `/login` или `/register`, он перенаправляется на `/` без изменения `isAuth`.
- `isAuth` меняется только при отправке формы входа и при подтверждении выхода.
- `LoginPage`, `RegisterPage`, `CardsPage` и `NotFoundPage` являются полноценными страницами со Styled Components.
- `CardPage`, `NewCardPage` и `ExitPage` находятся в `src/pages` и отображаются как модальные экраны. Их закрытие или отмена ведёт на `/`; они также стилизуются через Styled Components.
- Путь добавления карточки выбран как `/new-card`, потому что отдельная страница обязательна, но её адрес не указан в исходном списке маршрутов.
- 404 показывает ссылку на `/`, если пользователь авторизован, и на `/login`, если нет.
- После ручного обновления `useState` снова равен `false`; защищённый URL ожидаемо переводит на `/login`.

## Поток переходов

1. Неавторизованный пользователь открывает защищённый URL и попадает на `/login`.
2. Пользователь может перейти между `/login` и `/register` без перезагрузки.
3. Отправка формы входа меняет `isAuth` на `true` и переводит на `/`.
4. На главной доступны несколько учебных карточек с разными ссылками `/card/:id`, а также переходы на `/new-card` и `/exit`.
5. На `/card/:id` значение `id` читается через `useParams` и явно показывается при каждом переходе.
   Для неизвестного `id` страница сохраняет этот `id` на экране и показывает сообщение «Карточка не найдена»; это не глобальная страница 404.
6. Закрытие карточки, формы добавления или отмена выхода возвращают на `/`.
   Отправка демонстрационных форм карточки также возвращает на `/` без изменения данных.
7. Подтверждение выхода меняет `isAuth` на `false` и переводит на `/login`.
8. Любой неизвестный URL показывает 404.

## Рассмотренные подходы

1. **Vite в корне — выбран.** Удобный запуск для проверяющего и чистая React-структура в текущем репозитории.
2. **Ручная настройка сборки.** Полезна для изучения конфигурации, но отвлекает от маршрутизации.
3. **Vite в подпапке.** Изолирует старые файлы, но усложняет структуру и запуск проекта.

## Проверка результата

- `npm run dev` запускает приложение, `npm run build` завершается без ошибок.
- Все семь страниц существуют в `src/pages`.
- Каждый обязательный URL открывает ожидаемую страницу без полной перезагрузки.
- Все защищённые URL при `isAuth=false` переводят на `/login`.
- Вход и выход работают только через UI и меняют состояние предсказуемо.
- В уже авторизованной сессии переходы по ссылкам на `/card/1` и `/card/42` явно показывают разные значения `id`.
- `/card/999` явно показывает `id` и сообщение «Карточка не найдена».
- Регистрация переводит на `/login`; ссылки между формами работают без перезагрузки.
- Закрытие карточки/новой карточки и отмена выхода возвращают на `/`.
- Неизвестный URL показывает 404.
- После обновления защищённого URL авторизация сбрасывается и пользователь оказывается на `/login`.
- В `App.jsx` нет логики списка карточек.
- Все страницы, включая модальные экраны, используют Styled Components.
- `node_modules` и `dist` не попадают в Git.
